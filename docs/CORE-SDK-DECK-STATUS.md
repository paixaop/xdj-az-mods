# Passive deck status

The development service appends `on_deck_status` and `deck_status_release` to `az_library_v1`. The field and source coverage below applies to this service. The legacy snapshot, ticket and command APIs have separate coverage. [Public contract](../src/azmod/azmod-mod.h) · [Legacy evidence](CORE-SDK-SUPPORT.md)

For READY NATIVE `LOAD.state == AZ_STATUS_LOAD_LOADED`, the nonzero public `event.load_epoch` is the matched native load generation. The native reducer publishes `AZN_LOAD.load_generation` as the boundary epoch; loading, failure and withdrawal use zero. The storage worker can publish a READY `LOAD.track` only under that same epoch and its correlated source pin. INITIAL, CHANGE and RESYNC copy the image's epoch without translation. A client joining a qualified status track to `deck_snapshot.native_load_generation` must require exact generation equality and retain the track's READY load-scoped receipt. This rejects an older callback after the native player has already adopted a replacement. ## Field evidence

Timestamp decisions use `compare_timestamps()` with explicit invalid-result handling. The native receipt retains the actual observation window and source rate for each endpoint. Grid and cue publications retain their original integer coordinates alongside the public seconds representation, including signed grid offsets. The reducer copies those coordinates into its bounded immutable storage and preserves them across delayed delivery. Phrase boundaries, beat phase and loop-wrap classification use those clocks. A departure one sample past LOOP OUT is compared within its measured render window. An unobserved playback write is excluded from track history only after the load observer confirms that its epoch was revoked and no replacement load is active. A read that is briefly unavailable in the same epoch does not establish retirement. For pad mode, a fresh read after an unchanged ALT refresh can defer while the slot is busy or native layer dispatch is in progress. The selector can then withdraw the old observations and run its native PadState callbacks before the periodic refresh attempts to seed the selected deck. An isolated unchanged certificate update also leaves the writer slot alone. A missed changed writer or overlapping certificate writes still report capture loss, and an already poisoned slot stays stale until a fresh read succeeds.

## Measurement output

Create `/home/root/settings/azmod.deck-status.metrics` before EP147 starts to enable the optional diagnostic writer. It publishes `/tmp/azmod-deck-status.stats` by atomic replacement once per second. Counters include callback count, RESYNC count, capture and revision loss cuts, journal occupancy high-water mark and eviction count per deck. Eviction means an old record was reclaimed. A consumer that had delivered it incurs no loss. The file also records the peak of dynamically allocated revision bytes, fixed reducer storage, each mod owner's slow callback count, and its longest callback. Discrete and motion latency buckets measure producer observation to callback entry. Values are integer millisecond upper bounds and a percentile above 250 ms is reported as −1. Compare audio underruns separately at the engine.


The same metrics switch enables a bounded internal provenance journal with 16,384 records. It records committed gap cuts, their FILE source and physical binding, original and derived loss masks, fenced recovery or retirement, and each subscriber’s RESYNC delivery and prior cursor. Per-deck counter baselines are captured when diagnostics start. The journal never wraps: exhaustion sets a sticky failure, and missing, overwritten or unmatched evidence cannot justify an accepted loss. The writer exports the immutable recorded prefix with each metrics snapshot. [Provenance records](../src/azmod/sdk_status_proof.h) · [Metrics export](../src/azmod/sdk_status_metrics.c) · [Attribution regressions](../tests/unit/sdk_status_proof_test.c)

`provenance_bytes` reports the fixed journal reservation; `provenance_touched_bytes` reports its header and populated records. The fixed reducer total includes that reservation. With diagnostics disabled, the journal remains reserved in static storage but its records are not initialized or populated and the metrics writer does not run. Enabled producer work is a bounded scalar copy under the existing reducer serialization, with no producer-side allocation or file I/O. The metrics thread performs export. Include both reserved storage and touched memory in paired resource measurements.

A committed database-version change establishes unknown FILE history rather than its intermediate values. A failed or unstable FILE read can also end observation continuity. The worker reports the affected FILE components before a fenced baseline, or publishes their unavailable recovery when a safe read cannot be obtained. Acceptance must match those exact source-scoped cuts, subscriber deliveries and recovery receipts. A topic mask by itself cannot excuse native capture contention, queue loss, a missing saved revision or an unaccounted subscriber skip. These remain failures even when a legitimate FILE gap occurs nearby.
